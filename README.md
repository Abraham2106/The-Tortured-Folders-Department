## Overview

The Tortured Folders Department is a local-first Electron desktop app for reorganizing files with natural language.

It currently supports two complementary workflows:

- `Workspace`: choose a folder, describe how it should be organized, inspect the generated plan, and approve execution.
- `The Intake Desk`: watch inbox-style folders, extract text from incoming documents, classify them with AI, and auto-file them into a source-of-truth hierarchy.

The project is designed around a simple promise:

> File organization should feel conversational, inspectable, and safe.

---

## Current Capabilities

### Profile-Based Sessions

- Multiple local profiles on the same machine
- Separate history per profile
- Local SQLite persistence
- Theme-ready profile model

### Conversational Workspace

- Folder picker before each organization session
- Chat-driven planning from natural language instructions
- LLM responses constrained to structured JSON plans
- Resizable split view between chat and diff preview

### Smart Folder Analysis

- Directory tree context is sent to the planning engine
- Large folders are summarized with filename pattern analysis
- Date-based patterns such as `Screenshot 2025-04-*` are detected automatically
- Plans prefer glob patterns instead of file-by-file instructions

### Preview Before Execution

- Proposed operations are rendered as a visual diff list
- Supported actions:
  - `mkdir`
  - `move`
  - `move-dir`
- Execution only happens after explicit user approval

### Safe File Operations

- No delete operations are generated by the planning engine
- Existing targets are skipped instead of overwritten
- Parent directories are created automatically when needed
- Every execution is recorded as a transaction

### History and Reversal Flow

- Transaction history per profile
- Status tracking for completed, partial, or failed runs
- Rollback flow exposed from the History view

### The Intake Desk

- Configurable watch folders for incoming files
- Configurable "source of truth" root folder
- Auto-generated structure map from the chosen hierarchy
- Real-time worker-based file watching with `chokidar`
- Live activity log in the UI

### AI-Powered Auto-Filing

- Supported intake formats:
  - `.pdf`
  - `.docx`
  - `.md`
  - `.txt`
- PDF text extraction via `pdf2json`
- DOCX text extraction via `mammoth`
- Fallback classification by filename when text extraction fails
- Auto-move only when classification confidence is high

## Application Flow

### Workspace

1. Create or select a local profile.
2. Open a target folder from the chat panel.
3. Describe the organization rule in plain language.
4. The app scans the folder, generates a structured plan, and converts it into concrete diffs.
5. Review the proposed operations in the right panel.
6. Approve execution to apply the changes locally.

### Intake Desk

1. Add one or more watch folders.
2. Set a root folder that represents the canonical archive structure.
3. Drop supported documents into a watch folder.
4. A worker extracts text, requests the truth-source map, classifies the file, and executes the move when confidence is high.
5. Monitor progress from the live activity panel.

## Environment Variables

Create a `.env` file in the project root:

```env
ANTHROPIC_API_KEY=sk-ant-your-key
ANTHROPIC_MODEL=claude-opus-5
```

You can also set the API key and model from the in-app Settings screen; values entered there are stored locally and take precedence over the `.env` file.

### LLM Integration

Both the chat planner (`electron/logic/instruction-engine.js`) and the intake worker (`electron/workers/intake-worker.js`) call the Claude API directly via `@anthropic-ai/sdk`'s `messages.create`, using the configured `ANTHROPIC_API_KEY` and model.

## Scripts

```bash
npm run dev
npm run build
npm run lint
npm run test
npm run audit:fs
```

### What They Do

- `npm run dev`: starts Vite and Electron together
- `npm run build`: builds the frontend into `dist/`
- `npm run lint`: runs ESLint across the project
- `npm run test`: runs Vitest
- `npm run audit:fs`: fails if restricted delete-like filesystem calls are detected inside `electron/`

---

## Safety Model

- The chat planner is instructed not to generate delete operations.
- The execution engine only handles create and move-style actions.
- Target collisions are skipped instead of overwritten.
- Transactions are stored locally in SQLite for auditability.
- The app operates on user-selected folders rather than scanning the whole machine.

## Current Notes

- Frontend production build is configured with `npm run build`.
- Electron packaging/distribution is not yet scripted in `package.json`.
- The automated intake flow is currently optimized for text-bearing documents rather than images or arbitrary binaries.
- The existing tests focus on profile database behavior; broader integration coverage can still be expanded.
